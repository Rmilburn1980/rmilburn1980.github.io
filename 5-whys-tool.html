5 Whys Root Cause Tool

Define the problem, ask why with evidence at each step, test the logic in reverse, then set actions and check they worked. Supports the Analyse phase of the DMAIC project board.

How to use this tool
  • Define the problem with what, where, when and how big. A vague problem gives a vague root cause.
  • Answer each why from evidence, not opinion. Go and look at the process, then tick how you know.
  • Five is a guide. Stop when you reach a cause in the process or system that you can fix. Add or remove whys as needed.
  • Watch for blame. If the answer is a person, ask why the system allowed it.
  • Test in reverse. Read the chain from the root cause back to the problem. If the root cause were fixed, would the problem have been prevented?
  • Close the loop with containment, corrective and preventive actions, and a measure to verify the fix held.
  • If the problem has several causes, use a fishbone first and run one 5 Whys per branch.
